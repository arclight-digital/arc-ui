title: "Sheets That Stay Out Of The Way, And Three New Components"
---

A sheet that can rest at a peek height, sheets and drawers that don't block the page, three new components, and fixes, two of them to where sheets appear on screen.

### Snap Points

A bottom sheet can rest at several heights:

```html
<arc-sheet heading="Now playing" snap-points="140px, 70dvh"> … </arc-sheet>
```

Drag the handle between them. On release the sheet goes to the nearest height, or to the next one if you flicked it, and dragging well below the smallest closes it. The handle is also a slider: focus it and use the arrow keys. `snap` holds the current index, and `arc-change` fires when the user moves it. The heights are CSS lengths, listed smallest first, so `dvh` works.

### Sheets And Drawers That Don't Block The Page

**`no-modal`** on `arc-sheet` or `arc-drawer` makes it float above a page that stays usable: no backdrop, no scroll lock, nothing behind it made inert. Opening it **leaves focus where it was**, so a peek strip never interrupts someone reading or typing. Escape closes it only while focus is inside it, and closing it hands focus back if it had it.

```html
<arc-sheet heading="Brain" no-modal snap-points="120px, 88dvh"> … </arc-sheet>
```

Modal remains the default. Nothing changes unless you set `no-modal`.

### New: `arc-bar-list`

Labelled horizontal bars with their values, ranked: "which of these, and by how much" in less room than a chart.

```html
<arc-bar-list label="Traffic sources" items='[{"label":"Search","value":482},{"label":"Direct","value":311}]'></arc-bar-list>
```

`limit` keeps the top few, `max` puts several lists on one scale, `unsorted` keeps your order, and a row's `display` text formats its value. It is an ordered list, so every row reads as its label and value.

### New: `arc-field-list`

A form field that repeats, such as the options of a poll or the levels of a scale. Each row is an `arc-field-row` with your inputs, a handle to reorder it (arrow keys or drag) and a Remove button, and the list adds an Add button.

**Your application owns the rows.** The list fires `arc-add`, `arc-remove` and `arc-move`, and you update your array. It handles the rest: `min` and `max`, focus after each change, and a spoken confirmation for screen reader users.

### Settings Navigation

`arc-settings-layout` gets **`arc-settings-nav-item`**: links to the sections of a settings page, with an active state that follows the URL hash. With **`sections`**, the layout shows only the section whose `id` matches the active item, so a shared link or the back button lands on the right one. On a phone the nav becomes a scrolling row of tabs.

```html
<arc-settings-layout sections>
  <nav slot="nav" aria-label="Settings">
    <arc-settings-nav-item href="#profile">Profile</arc-settings-nav-item>
    <arc-settings-nav-item href="#security">Security</arc-settings-nav-item>
  </nav>
  <section id="profile">…</section>
  <section id="security">…</section>
</arc-settings-layout>
```

### `resetStyles`

`@arclux/arc-ui/shared-styles` now exports **`resetStyles`**: only `box-sizing: border-box`, for components your application writes itself. `tokenStyles` also zeroes margins and padding, which restyles a component that wasn't written for it.

### Deprecated: `arc-popover`'s `trigger`

It was documented as reserved for future trigger modes and never did anything. It still does nothing, and v5 removes it. For a panel that opens on hover, use `arc-hover-card`.

### Fixed: Sheets Opened At The Wrong Edge

A **bottom sheet rendered at the top of the screen**, and a **right sheet opened on the left** at its content height instead of full height. The browser's built-in styles for `<dialog>` pin every edge, and the sheet overrode only half of them. This has been the case since the sheet moved onto `<dialog>` in 4.0. Both edges are now tested, modal and non-modal. If you corrected the position yourself with `::part(panel)`, you can remove the workaround.

### Fixed: Row Actions Are Beside The Row

4.5.0's `arc-list-item` actions failed the accessibility audit (`nested-interactive`): the buttons were rendered inside the row element, which is an `option` in a selectable list and a link when the row has an `href`. They now sit **beside** the row, and in a plain list the list item wraps both. The page looks the same.

**Selectable lists don't render actions**, because a listbox can contain only options. `@arclux/arc-ui/dev` warns if you put them there. For a list of documents with a current one and per-row actions, use a plain list, and mark the current row with `href` and `selected`. That now sets `aria-current="page"`.
