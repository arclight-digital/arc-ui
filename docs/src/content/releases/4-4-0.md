Four more items from the application behind 4.3.0. One of them, reported as a styling issue, turned out to be a behaviour bug.

### Disabled Menu Items Were Not Disabled

In `arc-dropdown-menu`, `disabled` did nothing. It was reported because a disabled item looked exactly like an enabled one. The component also never read the attribute, so a disabled item could be clicked, reached with the arrow keys and chosen, and it fired `arc-select` like any other. `arc-context-menu` always handled it correctly, and the dropdown now matches it: disabled items are drawn muted with a default cursor, marked `aria-disabled`, skipped by the keyboard, and never selected.

If you worked around this by checking `disabled` in your `arc-select` handler, that check is now redundant but harmless.

The same pass found that the dropdown reported two different `index` values for one item, depending on whether it was clicked or chosen from the keyboard. Both paths now report the item's position among the menu's children, as `arc-context-menu` does. If you dispatched on `index` from keyboard selections in a menu with dividers, check your handler. Matching on `value` is more robust, and it's what `value` is for.

### Group Headings: `arc-menu-label`

```html
<arc-dropdown-menu>
  <arc-button slot="trigger">Ask</arc-button>
  <arc-menu-label>Physics</arc-menu-label>
  <arc-menu-item value="kinematics">Kinematics</arc-menu-item>
  <arc-menu-item value="optics">Optics</arc-menu-item>
  <arc-menu-label>Chemistry</arc-menu-label>
  <arc-menu-item value="bonds">Bonds</arc-menu-item>
</arc-dropdown-menu>
```

The items after a label form one group, named by the label for screen readers and headed by it visually. The label is never focusable and never selected. It works in `arc-dropdown-menu` and `arc-context-menu`, and every framework wrapper gains `MenuLabel`. Use it instead of a disabled item standing in as a heading.

### A Full-Width Trigger

`arc-dropdown-menu`'s trigger now fills the host when the host is given a width or `display: block`, so a card or a sidebar row can open a menu without `::part(trigger)`. By default it still shrinks to its content.

### A Select Value Stays On One Line

A narrow `arc-select` wrapped its value ("2026-09-" over "10") and grew a line taller. The value and the placeholder now stay on one line and truncate with an ellipsis, as `arc-tree-select` already did.
