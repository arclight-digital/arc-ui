title: "What Adoption Found"
---

The first application to adopt 4.6.0 sent back what it found. Most of it is fixed here, along with a focus bug the mutation gate caught.

### Fixes

- **`arc-settings-layout` on a phone** no longer widens the page. Inside a grid or flex parent, the tab row made the whole page 827px wide on a 390px screen. Revealing the active tab now scrolls only the tab row.
- **Hidden settings sections stay hidden**, even when a page rule sets `display` on them.
- **Plain-list rows respond to Enter and Space.** A row without `href` was focusable but did nothing from the keyboard.
- **Link rows let you route the click yourself.** `arc-select` is cancelable, and cancelling it stops the navigation. Ctrl-, Cmd-, Shift- and middle-clicks are left to the browser.
- **`size="sm"` lists get shorter rows**, not only smaller text (which didn't reach the rows either).
- **Closing a non-modal sheet from its own close button returns focus** to where it was, instead of dropping it on the page.
- **`arc-field-list`'s Add button** no longer prefixes "+ " to `add-label`. The plus is an icon, and your label is the whole text.

- **A grouped `arc-input` or `arc-select` no longer draws its own box inside `arc-input-group`.** The group's override only ever reached native inputs. The two controls now read `--input-border`, `--input-radius` and `--input-shadow`, which the group sets, and which any container of yours can set too.
- **Server-rendered pages hydrate cleanly with script-set data.** Every component whose data is an array (`items`, `rows`, `series`, `value` on the multi-value inputs, and so on) now renders its first, hydrating frame from what the server rendered, then takes the page's data. Fifteen components had no protection and ten had partial protection. A new test renders every one of them through the real server renderer.
- **`VirtualList`'s framework wrappers expose the element**, so `scrollToIndex()` is reachable from React, Vue and Preact as it already was from Svelte and Angular.

### Framework Wrappers (prism 3.2.0)

- **Svelte and Vue wrappers show their props' defaults again**: `density = 'default'`, `striped = true`, `columns = []`, and so on. Behaviour doesn't change, since the element always seeded its own default, but the wrapper now says what a prop starts as.
- **Svelte: a two-way binding may start `undefined`.** `let checked = $state(); <Checkbox bind:checked />` used to throw `props_invalid_value` on thirty props whose wrapper carried a fallback inside `$bindable()`. No wrapper does now; the element supplies the default.

### Additions

- **`arc-sheet` `persistent`:** a sheet the user can't dismiss, for a permanent peek strip. Dragging below the smallest height settles back on it, and there is no close button.
- **`arc-sheet` leaves out empty chrome:** no footer row without footer content, and no header on a persistent sheet with no heading.
- **`arc-bar-list`:** a per-item `highlight`, a `reference` line with its `reference-label`, and an "N more" line when `limit` leaves rows out (replaceable through the `more` slot).
- **`arc-field-list` `readonly`:** the rows, without their controls.

### Parents Say What Goes Inside

`custom-elements.json` now lists, for every component that reads child elements, which elements it expects and in which slot:

```json
"tagName": "arc-segmented-control",
"children": [{ "tagName": "arc-option" }]
```

```json
"tagName": "arc-settings-layout",
"children": [{ "tagName": "arc-settings-nav-item", "slot": "nav" }]
```

Twenty-seven parents carry it, from `arc-select` and `arc-tabs` to the menus and `arc-field-list`. Editor tooling and coding agents that read the manifest can now answer "what goes inside this?" without scraping the documentation. A check keeps the list equal to what each component actually reads, so it cannot drift.
