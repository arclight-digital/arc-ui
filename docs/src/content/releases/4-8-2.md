Server rendering now covers every component, not just the ones in the default bundle, and the plain-HTML package gets a round of fixes it had been missing for a while.

### Fixes

- **Every component server-renders.** `@arclux/arc-ui/ssr` registered components through the default barrel, which leaves out `arc-code-block` and the domain and experimental components, so the server never defined them and each rendered as an empty tag. Every code block reached no-JS readers, search engines and link previews with no code in it. The renderer now loads any component a page uses that isn't defined yet, through its own public entry. A code block's code, filename and copy button are in the server HTML; highlighting still arrives on the client, without replacing what the server sent.
- **`arc-page-layout` has its gap before it upgrades.** The gap was written from script only, so a server render had none until the component loaded. It now falls back to the `gap` default in CSS.
- **`@arclux/arc-ui-html` CSS.** Three generator bugs are fixed in the shipped stylesheets:
  - Variant and size rules now match only their own variant and size. Each one targeted `data-data-*`, so a rule like "every size but large" also caught large ones.
  - `arc-blockquote`'s opening mark shows. It printed the text "u201C".
  - Custom properties used as another property's fallback resolve.
- **The self-contained examples** in `@arclux/arc-ui-html` are rebuilt. They render in ARC's default dark theme with the page's font and color. Alerts, cards, inputs and buttons now look like the components. Hover and focus states show.
