title: "What the Server Saw"
---

A server-rendered page now looks the same before its script arrives as after. The components that build themselves from their children (breadcrumbs, navigation, tabs, menus, lists) used to arrive as empty frames and fill in on load. Now they arrive finished, and a new test holds every component to it. Astro's client router, long lightbox captions and a round of dependency updates are in too.

### Server rendering

- **Components render their children on the server.** A component that builds its shadow tree from its children read them only in the browser, so the server drew an empty frame and the page shifted when the script ran: no navigation without JavaScript, breadcrumbs that pushed the page down, every tab panel visible at once. The server now reads the same children, in the same way, before it renders. On load the browser adopts that markup instead of drawing its own. About fifty components are covered: navigation menu, breadcrumb, tabs, accordion, sidebar, scroll-spy, dropdown and context menus, select, radio group, segmented control, stepper, timeline, tree view, code group, settings layout and more.
- **What a component does to its children arrives with the page.** Inactive tab panels arrive `hidden`, a sortable list's items arrive in their rows, a description list's dividers arrive drawn.
- **Layout from props is in the server HTML.** `arc-dashboard-grid`, `arc-page-layout`, `arc-masonry`, `arc-aspect-grid` and `arc-notification-panel` wrote their columns, gaps and sizes from script. They're now part of the render.
- **`arc-prose` styles its content in the first paint.** Its styles for lists, links and inline code now arrive with the page, once per page rather than once per instance, and no longer get added among your content.
- **`arc-avatar` shows a loaded photo without waiting for script.**
- **`arc-truncate` arrives with its Show more button,** rather than growing by it on load.
- **Icons a component draws itself** (a carousel's arrows) are in the server HTML and its icon payload. So is the payload for a rendered fragment, which had none.
- **Any Lit element renders, not only ARC's.** Import another library's registration before rendering, `@arclux/brand/register` for example, and its elements arrive rendered too.

### Client-side routers

- **New: `@arclux/arc-ui/shadow-roots`.** A router that fetches the next page and parses it with `DOMParser`, as Astro's `<ClientRouter />` does, gets declarative shadow roots as dead templates. `attachShadowRoots(doc)` attaches them before the swap, so a soft navigation hydrates like a full load:

  ```js
  import { attachShadowRoots } from '@arclux/arc-ui/shadow-roots';
  document.addEventListener('astro:before-swap', (e) => attachShadowRoots(e.newDocument));
  ```

### Lightbox

- **A zoomed picture's caption moves to the bottom edge.** Left where it was, it covered the middle of the picture, which on a phone is most of what there is to see.
- **Long captions keep to three lines.** A **More** button opens the rest, which scrolls within two fifths of the screen. Before, a long caption could take most of a phone's screen and shrink the picture to fit.

### Fixes

- A `>` inside an attribute value, or component markup in one (a copy button's `value`), no longer confuses the server renderer.
- `@arclux/arc-ui/hydrate` warns if the part that reads children loads too late, the way it already warns about hydration support.

### Dependencies

`qrcode-generator` 2, which ships real ES modules. On the development side: ESLint 10, `globals` 17, and the docs on Astro 7. A few stay where they are, because moving them changes what consumers get: Angular, TypeScript 7 and the icon source. So does Vite for the Vue and Solid wrappers, since Vite 8 renames the Vue wrapper's published files.
