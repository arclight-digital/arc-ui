A second application, a Lit and Vite app built against 4.2.2, sent back fourteen items in one file. Six are fixed in code, five in documentation, and three are features that need design before they need code.

### ARC's Own Buttons Draw Without An Icon Pack

Since icons moved to `@arclux/arc-ui-icons` in 4.0, a page that had not imported a pack rendered ARC's own chrome blank. That meant the close buttons of `arc-dialog`, `arc-sheet`, `arc-drawer`, `arc-toast`, `arc-alert` and `arc-banner`, the move buttons of `arc-transfer-list`, the overflow of `arc-toolbar`, and the edit and play controls. The console explained why. A component whose own affordance breaks without an extra import is still a trap.

Core now carries the nine glyphs its components render. They are used only when no library is active or the active library lacks the name, so a registered pack still restyles them. They are drawn for ARC rather than copied from a pack, which keeps the core package's licence plain MIT. A check keeps the set equal to what the components render, so it cannot grow into a library.

### No Second Render From The Listbox Controls

`arc-select`, `arc-combobox`, `arc-multi-select`, `arc-tree-select` and `arc-tag-input` all scheduled a second render on first connect, and most did again on open, logging Lit's `change-in-update` warning each time. The shared controller asked for an update when there was nothing to reset, and three hosts moved virtual focus after the render it affects. Both are fixed, so every one of them now renders once.

### `arc-resizable` Takes A Handle On Either Edge

**`handle="start"`** puts the handle on the inline start (or the top, when vertical), for a panel docked against the far side of its container. Dragging the handle away from the panel grows it on either edge.

Working out that rule found an existing bug. The handle was placed logically and dragged physically, so in a right-to-left page it sat on the left and **dragging it outward shrank the panel**. It now mirrors correctly, for pointer and keyboard alike. If you worked around the old behaviour in RTL, remove the workaround.

### Sizing A Sheet

**`--sheet-max-height`** (bottom) and **`--sheet-width`** (right) size the panel without `::part`. The default height moves from `80vh` to **`80dvh`**. On a phone, `vh` is measured with the browser chrome retracted, so a sheet opened under a visible address bar used to run its footer off the screen.

### Two Tokens

- **`--chart-1-rgb` … `--chart-6-rgb`**: channels for tinting a series, as the accents and statuses already had, so `rgba(var(--chart-2-rgb), 0.35)` replaces a hard-coded triplet. They follow the light-mode shifts with their solids.
- **`--ui-size: 14px`**: dense interface text such as a chip, a toolbar button or a meta line, the step the scale jumped over between 12px and 16px. It pairs with `--ui-lh`. It is a role rather than a scale step, so there is no utility class.

### Documentation

- **Getting Started** now has a *Load the fonts* step. `base.css` names Host Grotesk, Tomorrow and JetBrains Mono and loads none of them, and without the step everything falls back to `system-ui` with nothing in the console.
- **Your Own Components**: a Lit component's shadow root does not see your global `box-sizing` reset. Adopt `tokenStyles` from `@arclux/arc-ui/shared-styles`, the styles ARC's own components start from.
- **Testing**: the children you write into `arc-dropdown-menu`, `arc-select`, `arc-segmented-control` and fourteen other parents are read as data and stay hidden, while the parent renders copies. Target the rendered copy by role and text.
- **Every parent's default slot now names its children** (`arc-option` elements, `arc-menu-item` and `arc-menu-divider` elements, and so on). This flows into `custom-elements.json`, web-types and the VS Code data, where tools and agents can find it.
- **Reduced Motion**: under the built-in rule an animation lands on the element's un-animated styles, so put the resting state in the base styles. A two-frame sprite is the worked example.

### Not In This Release

Snap points for `arc-sheet`, a non-modal mode for `arc-sheet` and `arc-drawer`, and a hover-revealed trailing action for `arc-list-item` were all asked for with good reasons. Each changes a contract (focus and dismissal for the first two, touch and keyboard reachability for the third), and each is getting a design pass before it gets a flag.
