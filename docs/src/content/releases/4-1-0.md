title: "The Documentation Catches Up With The Merges"
---

v4.0 merged thirteen components into survivors that first grew what they were missing. The survivors grew; their documentation did not. This release is that arithmetic finished — plus the imperative half of the API, which the docs had never rendered at all, and two checks so neither gap can reopen quietly.

Nothing here changes runtime behaviour. Every component source change in this release is JSDoc.

### The Absorbed Surface Was Undocumented

A merge grows the survivor and leaves its prose describing the component from before. Every absorbed variant is one the page does not know it has — and the page states a number, which is the load-bearing part: a reader told there are four does not go looking for a fifth.

Alert said four semantic variants and has five. Divider said five and has nine. Tag said six and has seven. Toolbar said two sizes and has three. In each case the missing value was fully implemented and named nowhere:

- **Alert** — `tip`, the `icon` slot, `live` and `density`, all from `arc-callout`. The page now also explains why `variant="info"` is `role="note"` rather than a live region, and that `live` is the override in both directions.
- **Divider** — `dashed`, `dotted`, `fade` and `line`, from `arc-separator`. `fade` and `subtle` read as the same idea and are not: `subtle` is the token gradient, `fade` is the flat one.
- **Description List** — `layout`, from `arc-key-value`. It composes with `columns`, which is about a different axis: `columns` is how many items sit across, `layout` is how one item arranges its own term and detail.
- **Data Grid** — `density`, `striped`/`no-striped` and `overscan`, from `arc-table` and `arc-data-table`. Three places on the page still recommended DataTable for read-mostly display; DataGrid *is* that tier now.
- **Tag** — `info`, from `arc-badge`.
- **Toolbar** — `lg` (60px), added when the size enum was canonicalised.

Badge described three of its seven variants and named `success`, `warning`, `error` and `info` nowhere. Each survivor now carries an absorption paragraph naming the exact translation, with the tombstone linked from the page that replaced it, so the reference works in both directions.

### Fixed — Advice Pointing At Components That Are Gone

A cut keeps its URL, so "use Callout instead" still lands the reader somewhere: on a tombstone that contradicts the advice that sent them. Eighteen such references across twelve pages. Nine said "use a Modal" — a rename is the worst case, because the sentence reads as perfectly sound English and describes a component that exists under another name. The rest pointed at DataTable, Dock, Event Calendar, OTP Input and Guided Tour.

### Components Document The Methods They Have

The docs data model carried props, events, slots and CSS parts, and no methods — so 78 public methods across 36 components appeared on no page. They now flow the same route everything else does: JSDoc → `custom-elements.json` → the page, `llms.txt`, the editor data, and `types/index.d.ts`, which gains a declaration for each of them.

Sub-components too. That section rendered props only, so `arc-hotspot`'s `close()` and `arc-sidebar-section`'s `toggle()` were in the manifest, in the `.d.ts` and in the editor data, and on no page — along with four sub-component events.

The prose caught up in the same pass. `arc-toast`'s `show()` was the case that started this: its options object grew a progress mode absorbing `arc-progress-toast`, and the only trace of it on the site was a sentence on the tombstone of the component it replaced. The page now covers progress mode, the action button from `arc-snackbar`, and the full lifecycle. Signature Pad's `clear()`, Sidebar Section's `toggle()`, Hotspot's `close()`, Form's `submit()`, Lightbox's `close`/`next`/`prev`, Inline Edit's `edit`/`commit`/`cancel`, Terminal's `play`/`reset`, Virtual List's `scrollToIndex` and Typewriter's `replay` are all documented with what they are *for*.

### Fixed — `@arclux/arc-ui-icons` Published No Types For Its Deep Imports

All five of the package's JavaScript subpaths resolved to an untyped `.js`: both packs' per-glyph wildcards, both register modules, and `./aliases`. A single-glyph import — the one the README recommends over the barrel — was `TS7016`, implicitly `any`:

```ts
import check from '@arclux/arc-ui-icons/phosphor/check';   // was: any
```

The barrels at `./all/phosphor` were typed from the start, so the package looked typed from outside while the deep import was not. Both wildcards now point at one shared declaration rather than a `.d.ts` per glyph, which would have meant 3,408 extra files in every install to say `string` 3,408 times.

If you worked around this with a local `declare module` for the icons package, you can drop it.

### Three New Checks

Each of the above is now something the build refuses rather than something a reader finds.

- **`prose-counts`** compares every "N variants"/"N sizes" claim on a docs page against the enum in `custom-elements.json`, which is generated from the `oneOf()` the component declares — so it cannot drift the way the prose did. Subset claims ("five illuminated variants" of nine) and usage limits ("do not mix more than two") are skipped, and the skipped count is printed rather than left implicit.
- **`removed-references`** reads the prose fields of every page and excuses a mention of a removed component only when the sentence or paragraph holding it links the tombstone or says the component is gone. Previews and tabs are not scanned: demo content naming a component is illustrating it, not recommending it.
- **`export-map`** gains the assertion that every JavaScript subpath in every published package reaches a declaration file. `generate-exports.js` has asserted this since 4.1 — but only for `@arclux/arc-ui`, whose map it writes; the icons map is hand-written and was covered by nothing. The check reads every published map, whoever wrote it.

`generate-types` also fails the build now on a public method with no `@returns`, rather than assuming `void`. A plain-JS body tells the generator nothing, so "no `@returns`" means nobody wrote one — and four methods, three of them `async`, had shipped into `types/index.d.ts` declared `void` while returning a `Promise`.

### Upgrading

Nothing to do. No prop, event, slot, CSS part or behaviour changed.

Two notes for TypeScript consumers, both from new declarations rather than new API. Single-glyph icon imports are typed `string` where they were `any`, so code that leaned on the `any` will now be checked. And element classes now declare their methods, so a typed ref reaches them without a cast — `useRef<ArcToast>(null)` gets `show()`, `updateToast()` and `complete()` with the shape of the options object.
