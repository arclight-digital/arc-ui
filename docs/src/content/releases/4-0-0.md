v3 consolidated how the components behave; v4 decides what the library is: an application UI kit, usable from any framework without changing your design system. The catalog is curated instead of accumulated, the props enforce their documented contracts, the overlays run on the platform's own `<dialog>`, and theming is two colors in with everything else derived.

Every change in this release serves that sentence, and the breaking ones are its cost — each is mechanical, and [MIGRATION.md](https://github.com/arclight-digital/arc-ui/blob/main/MIGRATION.md) records every one with the fix beside it. The arithmetic, since the count is a consequence and not the pitch: 207 registered tags in v3.2 are 189 in v4.0 — five deleted, thirteen merged away or renamed — with 173 in the default barrel and the rest a deliberate import away. v3 keeps everything and receives patches for a quarter after this tag.

### Breaking — Eighteen Tags Leave The Catalog

**Five components are deleted**: `arc-guided-tour`, `arc-spotlight`, `arc-speed-dial`, `arc-dock` and `arc-event-calendar`. Each shipped as stable while broken in the first way a consumer would touch it — a tour that could not point inside a shadow root, a speed dial whose closed actions stayed in the tab order, a dock whose only reveal was `:hover`, a calendar that could not say "Tuesday at 2pm". Every deleted tag keeps its docs URL as a tombstone naming the reason and the alternative, so a bookmarked link explains itself rather than 404ing. The tour's replacement, `arc-tour`, is a planned rebuild on the v4 overlay contract taking element references instead of selectors; its tombstone will be updated when it lands.

**Thirteen more merge into survivors that first grew what they were missing**: `arc-separator` into `arc-divider` (which gained `line`, `dashed`, `dotted` and `fade`), `arc-key-value`/`arc-kv-pair` into `arc-description-list` (which gained `layout="horizontal"`), `arc-cluster` into `arc-stack`, `arc-otp-input` into `arc-pin-input`, `arc-callout` into `arc-alert`, `arc-snackbar` and `arc-progress-toast` into `arc-toast` (which gained a real progress mode), `arc-inline-message` into every form control's own `error` prop, and the table family — `arc-table`, `arc-data-table`, `arc-column` — into `arc-data-grid`, all three now windowing through one shared `VirtualController` with `overscan` public. Each row's exact prop translation is in MIGRATION.md.

One merge on the plan did not survive contact with the pixels: `arc-badge` is **not** folded into `arc-tag`, because badge is mono sentence-case and tag is a tracked uppercase label — merging would have re-set every version badge on every page in a label face. Both stay until the type-scale question is settled honestly.

And one behaviour change rides the callout merge that affects existing `arc-alert` users: `variant="info"` renders `role="note"` now, not a live region. A new `live` prop (`auto | off | polite | assertive`) is the override in both directions, because severity asks "how bad is this" while a live region asks "did this just appear" — different questions, and no prop can infer the second from the first.

### Breaking — Marketing And Media Leave The Default Barrel

The catalog was flat, so every question about the landing-page cluster and the DAW primitives came out as *delete or exile?* — and both answers were wrong. v4 adds the axis those questions were missing: twelve marketing components (`arc-carousel`, `arc-cta-banner`, `arc-typewriter` and friends) now import from `@arclux/arc-ui/marketing`, and `arc-knob`, `arc-level-meter`, `arc-waveform` and `shared/time-scale` from `@arclux/arc-ui/media`. Same package, same version, same test suite — a satellite package is where components go to die, and these are neither dead nor exiled. Per-component subpaths are untouched, so `@arclux/arc-ui/carousel` works exactly as before; what changed is that a default import in an admin dashboard no longer puts a rotary synth knob in the module graph.

Every component now declares a `status` — 179 stable, 10 beta, and `experimental` is gated out of the default barrel from birth, so no future addition ever enters it only to be removed inside a major. Nothing is experimental at v4.0, which is the point of landing the gate early.

### Breaking — The Overlays Run On A Real `<dialog>`

`arc-dialog` (né `arc-modal`), `arc-sheet`, `arc-drawer`, `arc-lightbox` and `arc-command-palette` render a real `<dialog>` opened with `showModal()`. Focus containment, page inertness, Escape and focus restore come from the browser; panels paint in the top layer, so an overlay inside a `transform` no longer loses to a stacking context. The scrim is `::backdrop` now — style it through `--dialog-backdrop` and friends, since a pseudo-element cannot carry a part — and an `autofocus` on your own slotted content finally wins the initial focus.

Three tags became two along the way, and it is the one migration where a surviving name changes meaning: `arc-modal` is renamed `arc-dialog`, and the old `arc-dialog` — which was a confirm prompt — is absorbed by `arc-confirm`. The new `arc-dialog` writes a `console.error` naming `arc-confirm` when handed `message` or `confirmLabel`, so upgrading into the wrong element is loud instead of blank.

Two neighbours improved on the same pass: `arc-navigation-menu` collapses on its own width rather than the viewport's (a nav squeezed into a genuinely narrow column hides its pill row instead of overflowing), and `arc-context-menu` dismisses through the shared controller instead of an invisible full-page backdrop, so the click that closes it reaches what it was aimed at and tabbing away dismisses too.

### Breaking — One Dialect: prefix/suffix, dismissible, Real Arrays

The side slots on `arc-toolbar` and `arc-status-bar` are `prefix` and `suffix`, matching the five components that already spelled them that way. `arc-dialog.closable` is `dismissible`. `size` scales read `sm | md | lg` everywhere, with the exceptions carrying written reasons.

Array props are the deeper half. Every array prop in the library — 26 props across 19 components — is declared through one `list()` primitive, which settles what four hand-rolled dialects each got wrong: a malformed attribute falls back to the declared default instead of throwing from a place nothing can catch, a removed attribute returns to the default instead of `null`, and defaults are factories so two elements cannot share one mutable array. Six property-only props (`arc-lightbox.images`, `arc-uptime.data` and friends) gained JSON attributes, so a server-rendered page can finally set them. `arc-comparison`'s two JSON-string props take real arrays on the property path — markup unchanged — and the generated wrapper types moved with them in all six packages, so a TypeScript consumer gets a compile error rather than a silent empty render.

### Breaking — Icons Move To `@arclux/arc-ui-icons`

The two icon packs were 88% of every file the core package published, in every install, whether or not anything rendered an icon. They are their own package now — core drops from 3,895 files and 8.5 MB unpacked to 476 and 4.8 MB — and registration is explicit: `import '@arclux/arc-ui-icons/phosphor'` is the one line that restores v3's behaviour exactly. There is no default library any more, because core ships no icons and naming a default would be a promise it cannot keep; upgrading without the package renders slot fallbacks and logs one line containing the fix. The registration seam is public, so your own icon set arrives through exactly the door Phosphor does — aliases included, which is how built-in components resolve against a custom library.

Also settled here, because it was a compliance defect: both packs' licenses now travel with the package, generated from the installed upstreams so a relicense shows up as a diff.

### Changed — Props Enforce Their Own Documentation

A long-standing shape, closed in bulk: constraints that lived where a value was *used* rather than where it is *held*, so the render obeyed the rule while the property did not. Per-item `disabled` is honoured everywhere it was documented — `arc-tab` gained the property its docs promised, and `arc-option.disabled` now works in all four of its consumers through one shared listbox option. Numeric bounds moved onto declarations, so the property you read back is the value in use; `arc-stepper-nav`'s button and handler agree by construction now, where previously the button said "Next" while the handler submitted. Fourteen props whose *unset* state is a third meaning — a gauge deriving its zones, a clock following the viewer's locale — are declared `nullable` rather than being collapsed onto a default.

Three event payloads that named the wrong thing were fixed and are collected in MIGRATION.md because "it was broken" is no comfort to code that read the broken value: `arc-date-range-picker`'s `detail.value` is the ISO interval string its `value` property always was, `arc-tree-view` keys nodes by path rather than label (two files named `index.js` are two nodes), and `arc-list`'s selection survives a comma.

### Changed — Every Root Is `::part(base)`, Every Text A Type Context

The library had 86 distinct spellings of "the root element" across its parts. Every component's root now carries `base` alongside the name it already had, so `arc-anything::part(base)` works without looking up what a component calls its outer box. Nothing is renamed; the exceptions are components whose host *is* the box, listed with reasons.

Typography went through the same consolidation: text is described by a type context — `ui`, `glyph`, `numeral`, `label` — rather than assembled from literals. A census had found `font-weight: 600` written out 39 times, the label role's own weight, in components that could not follow the role when it moved. Label tracking is 2px everywhere now instead of five spellings of one treatment, and a build check fails on a literal or on a `var()` naming a token nothing declares — which is how `arc-command-palette` was discovered to have been rendering its hard-coded fallback since the day it was written.

### New — The Theming API Is Two Colors

Named, checked, and now the whole contract: `--accent-primary` and `--accent-secondary` (with their `-rgb` channels) are the inputs, thirty-five tokens follow them, and statuses, chart colors, all four schemes and the high-contrast preset derive at build time through the OKLCH pipeline. A build check fails on a token that spells the brand instead of referencing it — the failure it exists for is the local rescue, a pinned literal where the brand quietly stops.

The high-contrast theme is generated by the same solver as the shipped schemes, and its AAA claim is true for the first time: ten of its thirty pairings had measured under 7:1, two of them under 5. The solver also takes its final step on the 8-bit value that actually ships, which moved 24 tokens in base.css by one channel — invisible, except that the 5.5:1 contract is now true of the file rather than of the search.

`[data-density="compact" | "comfortable"]` is new and additive: the spacing scale restated at 0.75× and 1.25×, on the page or on a region. Touch targets stay at the WCAG 24×24 minimum and type does not move, because tightening a layout and shrinking text are different decisions.

### Fixed — Four Wrapper Defects That Had Always Shipped

v4 adds a runtime harness that mounts every wrapper package in a real browser and asserts one contract across all six frameworks. It immediately found four defects as old as the packages themselves. Angular defined no custom elements at all — every wrapper imported the element class into type position only, TypeScript elided it, and consumers were binding inputs onto an `HTMLUnknownElement`. Angular and Solid both discarded every child of the ten components whose slots are all named. Eighteen Vue and Solid subpaths resolved to files no build produced. And the React package's `createComponent` re-export is deprecated in favour of `@lit/react`.

On top of the fixes, the wrappers gained what each framework actually reaches for: **27 Angular controls implement `ControlValueAccessor`**, so `formControlName`, `formControl` and `ngModel` bind — they had worked on zero wrappers, failing silently with a pristine control beside a filled-in element. Preact and Solid ship JSX augmentations for native `<arc-*>` use beside their wrapper packages, the way React always had — and React's activation instruction, which had never worked (TypeScript never resolves a `types` entry through an export map), is replaced by two spellings that do, each compiled against its framework's own resolution on every build.

All six packages are generated by [prism 3](https://github.com/arclight-digital/prism), which ships alongside this release and absorbed the jobs arc-ui had been doing on its behalf — the Angular forms pass, the JSX augmentations, the wrapper export maps. The four wrapper checks stay regardless: they are the acceptance suite, and every fix in prism's ledger was found by one of them.

### New — The Test Suite Hardened Into A Contract

The verification layer grew with the release rather than after it: 4,929 tests across 124 files and 37 build-time checks, up from 21 checks and just under 4,000 tests when the cycle began. Behind the counts sit three structural changes.

A numbered findings ledger ran to 89 entries over the cycle and closed at zero — every finding either fixed with a regression test pinned behind it, or closed by the removal of its component. The shared modules every component leans on — the listbox, the positioning, dismissal and focus controllers, the props vocabulary — are gated by **mutation testing** in CI, ratcheted so a score can only rise: the listbox controller's kill rate went from 50% to 98.7% once it got a direct suite, and every surviving mutant is analysed as equivalent rather than left as a number. The lesson that pass taught is worth repeating: a measurement is only evidence if the thing measured can differ, and two of the oldest tests in the suite were asserting values that could not.

And the suites are increasingly **derived rather than written**: conformance asserts what each component's own declarations claim, the dismissal contract turns a docs page's "closes on Escape" into the assertion itself — with a completeness guard, so a new component declaring `open` fails until someone states whether it is dismissible — and the wrapper runtime harness above is one probe set run against all six frameworks. A derived test cannot drift from the surface it guards, and a checked claim cannot be documentation fiction.

### Also In This Release

`arc-toast`'s action button rendered for the first time (the payload was stored in one place and read from another, for every toast the component ever displayed), `arc-data-table`'s blank-table windowing bug died in the merge that retired the component, and publishing is diff-gated, so a release republishes only the packages whose files actually moved.

The docs pages of every removed component remain as tombstones, this changelog gained the archive block you are reading past, and the v3 branch receives patches for a quarter. If you are upgrading, [MIGRATION.md](https://github.com/arclight-digital/arc-ui/blob/main/MIGRATION.md) is ordered so the mechanical renames come first and the judgment calls last.
