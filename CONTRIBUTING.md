# Contributing to ARC UI

Thanks for contributing to ARC UI.

## Getting started

1. Fork the repository
2. Clone your fork and install dependencies (Node >= 24, pnpm >= 10):

```bash
git clone https://github.com/<your-username>/arc-ui.git
cd arc-ui
pnpm install
```

3. Start the docs site (the development playground):

```bash
pnpm dev
```

## Project structure

```
packages/
  web-components/   # Lit web components (source of truth)
  react/            # React wrappers      (GENERATED by @arclux/prism)
  vue/              # Vue wrappers        (GENERATED)
  svelte/           # Svelte wrappers     (GENERATED)
  angular/          # Angular wrappers    (GENERATED)
  solid/            # Solid wrappers      (GENERATED)
  preact/           # Preact wrappers     (GENERATED)
  html/             # Standalone CSS + HTML examples (GENERATED)
  icons/            # Phosphor + Lucide packs (GENERATED from upstream, plus a few hand-written modules in src/)
docs/               # Astro documentation site (arcui.dev)
shared/             # Design tokens: tokens.js (source), base.css (GENERATED)
scripts/            # The generate pipeline + static assertion checks
```

Never hand-edit generated files. `pnpm generate` recreates them all, and CI
fails any commit where the generated output doesn't match the source.

## Development workflow

### Adding or modifying a component

All components live in `packages/web-components/src/`, organized by tier:

- `content/`: static display (Card, Avatar, Accordion, …)
- `data/`: data display (Data Grid, Badge, Timeline, …)
- `typography/`: text (Prose, Code Block, Markdown, …)
- `input/`: form controls (Button, Input, Combobox, Date Picker, …)
- `navigation/`: nav (Sidebar, Tabs, Menubar, Breadcrumb, …)
- `layout/`: structure (App Shell, Container, Split Pane, …)
- `feedback/`: messaging and overlays (Dialog, Toast, Alert, Popover, …)
- `shared/`: mixins, controllers, and helper elements used across tiers

After any change, regenerate everything:

```bash
pnpm generate
```

This rebuilds tokens CSS, element registrations, all six framework wrapper
packages, the HTML/CSS package, `custom-elements.json`, the published type
declarations, editor integration data, and the README stats, and then runs
the static assertion checks (prop unions, enum fallbacks, wrapper slots,
child registrations, event conventions, wrapper typecheck). Commit the
regenerated output together with your source change.

### Testing

```bash
pnpm test          # web-test-runner + Chromium (packages/web-components/test/)
pnpm lint          # ESLint over hand-written source
pnpm audit:a11y    # axe-core audit of the built docs site (needs pnpm build:docs first)
```

All three run in CI. Tests favor cross-cutting invariants (font roles, enum
fallbacks, event conventions) over per-component snapshots. If you fix a
shipped bug, add a test that pins the invariant that broke.

### Conventions

- **Web components**: `arc-component-name` (kebab-case tag), `ArcComponentName` (PascalCase class)
- **React wrappers**: `ComponentName` (no Arc prefix)
- **Events**: `arc-event-name` with `bubbles: true, composed: true` (checked by `pnpm check event-conventions`)
- **Child elements**: if a component renders another `arc-*` element, declare it
  with a `@requires` JSDoc tag so per-component imports register it (checked by
  `pnpm check child-registrations`)
- **Styles**: components import `tokenStyles` from `../shared-styles.js`. A few
  elements with no transitions of their own, mostly children such as `arc-tab`
  and `arc-radio`, leave it out.
- **Tokens**: edit `shared/tokens.js` only; use `var(--token)`, never hardcode
  colors, spacing, or font families (font faces are role slots, see the
  typography docs)
- **JSDoc**: component JSDoc generates the docs API tables, the type
  declarations, and the editor data.
- **Announce every change to a shared prop.** If a component assigns to one of
  its own public props outside the constructor, every path that does it fires
  the event that reports the new value. Route them through one method
  (`arc-app-shell._setOpen()` is the pattern) instead of assigning in several
  places.

  `@arclux/prism`, the wrapper generator, treats a prop as two-way when the
  component assigns it outside the constructor and fires an event carrying the
  value. A prop with three announced paths and one silent one is generated as
  bindable, and the framework's copy goes stale whenever the silent path runs.
  The component's own tests won't catch it, because the stale copy is in the
  consumer's framework state. `arc-app-shell` shipped this
  bug: closing the drawer from the backdrop, Escape or a followed link was
  announced, and the resize from mobile to desktop width closed it silently.

### Pull requests

- Create a feature branch from `main`
- Keep PRs focused: one feature or fix per PR
- Say what changed and why in the description
- If adding a new component, include a docs page in `docs/src/data/components/`

## AI / LLM policy

ARC UI accepts contributions made with AI and LLM tools, on these terms:

- A human reviews and verifies all AI-generated code before the pull request is
  opened. The submitter is responsible for understanding every line in their
  PR, however it was produced.
- PRs pass all existing checks. Using AI tools doesn't exempt a contribution
  from them.
- If most of the code was AI-generated, say so in the PR description.
  "Authored with AI assistance" is enough.

Pull requests opened by fully autonomous agents, bots, or agentic services
(OpenClaw, Sweep, and the like) without meaningful human review **will be
closed**. If you use an agentic tool, review its output yourself and submit the
PR from your own account with your own sign-off.
